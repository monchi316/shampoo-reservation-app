# 運営側手順書: 新規企業オンボーディング

この手順書は、運営担当が **新しい企業（店舗）を追加して利用開始できる状態にする** までをまとめたものです。  
初めて担当する人でも、上から順に実施すれば進められる構成にしています。

---

## 0. この手順でゴールにする状態

以下ができれば完了です。

- 新企業の `tenant` が作成済み
- 企業オーナーが管理画面へログインできる
- 店舗設定（メニュー/営業時間/LINE設定）が投入済み
- 企業専用の予約URLで予約できる
- 予約通知/前日リマインダーが企業公式LINEから届く

---

## 1. 事前準備（開始前チェック）

- [ ] Supabase 管理権限

- [ ] 管理画面 owner/superadmin 権限
- [ ] 企業側から受領済み情報

  - 営業時間（通常/例外）
  - 企業公式LINEチャネル情報（後述）

## 2. 新規テナント（店舗）を作成する

Supabase SQL Editor で実施します。

### 2-1. `tenants` に1行追加

```sql
insert into public.tenants (id, name)
values (gen_random_uuid(), '株式会社サンプル')
returning id, name;
```

返ってきた `id` がこの企業の `tenant_id` です。必ず控えてください。

### 2-2. 初期スケジュール設定を作成

```sql
insert into public.tenant_scheduling_settings (
  tenant_id,
  business_hours_mode,
  uniform_open,
  uniform_close,
  avg_service_minutes_per_car,
  avg_travel_minutes,
  booking_lead_days,
  booking_lead_hours
)
values (
  '＜tenant_id＞'::uuid,
  'uniform',
  '09:00',
  '18:00',
  60,
  30,
  0,
  0
)
on conflict (tenant_id) do nothing;
```

### 2-3. 曜日設定（必要なら）

`business_hours_mode='weekly'` を使う場合は `business_hours_weekly` を投入します。  
（最初は uniform で開始し、管理画面から変更する運用が簡単です）

---

## 3. オーナーアカウントを作成する

## 3-1. パスワードハッシュを作る

リポジトリのスクリプトを使用:

```bash
node scripts/phase2-hash-password.mjs "初期パスワード文字列"
```

出力されたハッシュ文字列を控えます。

## 3-2. `admin_operators` に作成

```sql
insert into public.admin_operators (
  email,
  password_hash,
  display_name,
  is_active,
  is_superadmin,
  role
)
values (
  'owner@example.com',
  '＜ハッシュ文字列＞',
  '企業オーナー',
  true,
  false,
  'owner'
)
returning id, email;
```

## 3-3. テナント紐付け

```sql
insert into public.admin_operator_tenants (operator_id, tenant_id)
values ('＜operator_id＞'::uuid, '＜tenant_id＞'::uuid)
on conflict do nothing;
```

## 4. 企業のLINE連携情報を登録する

この部分は企業担当と連携して進めます。  
詳細は `docs/企業提供_公式LINE連携セットアップ手順.md` を参照。

必要情報:

- LIFF ID
- Channel ID
- Channel Secret
- Channel Access Token

登録場所:

- 管理画面 > 店舗設定 > LINE通知設定（企業別）

登録後:

- `状態: 設定済み` が出ること
- `LINE Push 通知を有効化` がONになっていること

---

## 5. 予約用リンクを作成して企業へ共有する

共有URL例:

```text
https://your-app.vercel.app/reserve?tenantId=<tenant_id>&lid=<liff_id>
```

注意:

- `tenantId` と `lid` は必ず同じ企業の組み合わせにする
- リッチメニュー更新時、古いURLが残らないようにする

---

## 6. 企業に渡す初期ログイン情報

最低限、次を引き渡します。

- 管理画面URL: `https://your-app.vercel.app/admin/login`
- 初期メールアドレス
- 初期パスワード
- 初回ログイン後にパスワード変更する案内

運営ルール:

- 初期パスワードは使い回さない
- メールやチャットで平文共有しない（可能なら別経路）

## 8. 障害時の切り分け（最短）

### 8-1. ログインできない

- `admin_operators.is_active = true` か
- `admin_operator_tenants` の紐付けがあるか
- メールアドレス入力ミスがないか

### 8-2. 予約はできるがLINE通知が来ない

- 店舗設定で `LINE Push 通知` がONか
- tenantの token が正しく保存されているか
- `line_delivery_logs` にエラーが出ていないか

### 8-3. 前日リマインダーが来ない

- `REMINDER_CRON_SECRET` 設定
- Cron実行ログ
- `reservations.reminder_sent` 状態
- `docs/reminder_sql_playbook.md` のSQLで対象を確認

---

## 9. 月次メンテナンス（推奨）

- 無効アカウント確認（退職者など）
- token更新有無の確認（企業側で再発行していないか）
- 送達失敗ログ（`line_delivery_logs`）の確認
